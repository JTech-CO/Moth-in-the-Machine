# Moth in the Machine

1947년 Harvard Mark II 컴퓨터의 릴레이에서 발견된 실제 나방, 그리고 당시 로그북에 남은 “bug” 기록에서 영감을 받은 브라우저 기반 3D 비행 게임입니다. 플레이어는 작은 나방이 되어 기계 내부 회랑을 날고, 전선·스파크·과열 릴레이·진공관 같은 위험을 피해 지정된 접점에 정확히 착륙해야 합니다.

**[브라우저에서 바로 플레이](https://jtech-co.github.io/Moth-in-the-Machine/)**할 수 있으며, 설치나 계정이 필요하지 않습니다.

## 게임 방법

1. 메인 화면에서 열린 난이도를 고른 뒤 원하는 단계를 선택합니다.
2. 비행 화면을 클릭해 마우스 포인터를 잠그고 회랑을 비행합니다.
3. 장애물과 위험 구역을 피하면서 HUD와 미니맵으로 목표의 방향·표면·고도를 확인합니다.
4. 목표에 접근한 뒤 `Space`로 착륙 준비 모드에 들어가 접점에 안전하게 닿습니다.
5. 남은 HP에 따른 별과 클리어 시간을 기록하고, 결과 이미지나 텍스트를 복사해 공유합니다.

목표는 바닥에만 있지 않습니다. NORMAL과 HARD에서는 천장이나 좌우 벽의 접점에도 착륙해야 하며, 목표 면의 안쪽 방향으로 정확하게 접근해야 합니다. 목표에 성공적으로 접촉한 결과는 즉시 확정되므로 이후 관성이나 충돌 때문에 실패로 바뀌지 않습니다.

## 19개 단계와 해금

캠페인은 전역 순차 진행이 아니라 **난이도 선택 → 개별 단계 선택** 방식입니다.

| 구분     | 단계 수 | 환경과 특징                                      | 해금 조건                        |
| -------- | ------: | ------------------------------------------------ | -------------------------------- |
| TUTORIAL |       1 | Relay Bay에서 비행과 표면 착륙 연습              | 처음부터 플레이 가능             |
| EASY     |       6 | Mark II Relay Bay의 기본 회랑과 장애물           | 튜토리얼 클리어                  |
| NORMAL   |       6 | Switching Gallery의 교차 게이트와 다중 표면 목표 | 서로 다른 EASY 단계 3개 클리어   |
| HARD     |       6 | Logic Labyrinth의 복잡한 데크·게이트·중앙 코어   | 서로 다른 NORMAL 단계 3개 클리어 |

같은 단계를 여러 번 클리어해도 해금 횟수에는 한 번만 반영됩니다. 단계별 최고 별과 최고 시간, 해금 진행도, 렌더링 품질 설정은 브라우저의 LocalStorage에 저장됩니다.

## 조작법

| 입력               | 동작                                                       |
| ------------------ | ---------------------------------------------------------- |
| 비행 화면 클릭     | 포인터 잠금 및 마우스 비행 제어 시작                       |
| `WASD` 또는 방향키 | 이동과 관성 비행                                           |
| 마우스             | 좌우 회전(yaw)과 상하 시야(pitch)                          |
| `Space`            | 착륙 준비 / 호버 모드 전환                                 |
| `T`                | 3인칭 / 1인칭 카메라 전환                                  |
| `P` 또는 `Esc`     | 일시정지                                                   |
| `R`                | 클리어·실패 결과 화면에서 현재 단계 재시작                 |
| `Enter`            | 클리어·실패 결과 화면에서 현재 난이도의 단계 선택으로 복귀 |

포인터 잠금이 풀리거나 브라우저 탭이 비활성화되면 비행·타이머·피해 판정이 함께 일시정지됩니다.

## HP, 기록과 공유

- 장애물 충돌과 위험 구역은 HP를 감소시키며 HUD의 체력계와 화면 가장자리의 붉은 피격 효과에 즉시 반영됩니다.
- HP가 0이 되면 단계에 실패합니다.
- 클리어 별점은 남은 HP 기준입니다: **100 HP = 3개**, **50 HP 이상 = 2개**, **1~49 HP = 1개**.
- 각 단계에는 최고 별과 최고 클리어 시간이 저장됩니다.
- 클리어 결과는 별·시간·HP가 들어간 1080×1080 PNG로 복사하거나 다운로드할 수 있으며, 텍스트 결과 복사도 지원합니다.
- 실패 후에는 같은 단계를 다시 시도하거나 단계 선택 화면으로 돌아갈 수 있습니다.

## 렌더링 품질

메인 화면 하단의 `QUALITY` 버튼으로 두 모드를 전환할 수 있습니다.

- **AUTO / ADAPTIVE**: 기기 성능에 맞춰 렌더링 해상도를 조절하면서 전체 장식과 안티앨리어싱을 유지합니다.
- **LOW SPEC**: 낮은 렌더링 해상도 범위, 비활성화된 안티앨리어싱, 줄어든 장식·조명을 사용해 저사양 환경의 프레임 유지에 집중합니다.

선택한 품질은 다음 방문에도 유지됩니다.

## 로컬 실행

요구 환경은 Node.js `>=20.19.0 <25`와 pnpm `>=10`입니다. 저장소의 `.node-version`은 권장 검증 런타임인 Node.js `24.14.0`을 지정합니다.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

개발 서버는 기본적으로 [http://localhost:5173/](http://localhost:5173/)에서 열립니다. 프로덕션 빌드를 로컬에서 확인하려면 다음을 실행합니다.

```bash
pnpm build
pnpm preview
```

## 기여 전 검증

```bash
pnpm verify
pnpm format:check
```

`pnpm verify`는 ESLint, TypeScript, 모듈 경계, Vitest 커버리지, 프로덕션 빌드와 번들 예산 검사를 순서대로 실행합니다. GitHub Pages용 하위 경로와 번들 예산까지 확인하려면 다음 명령을 사용할 수 있습니다.

```bash
pnpm build:pages
```

## 기술 스택과 지원 환경

- React 18, TypeScript 5, Vite 6
- Three.js, React Three Fiber, Drei
- Zustand와 LocalStorage 기반 클라이언트 상태·진행도 저장
- SCSS/CSS Variables와 자체 호스팅 Inter·Courier Prime 글꼴
- Vitest/V8 Coverage, ESLint, Prettier
- GitHub Pages 정적 배포: 백엔드, 로그인, 설치 과정 없음

게임은 WebGL2와 키보드·마우스를 사용할 수 있는 데스크톱 환경을 우선 지원합니다. Chrome, Safari, Edge, Firefox 최신 2개 버전을 대상으로 하며 Internet Explorer는 지원하지 않습니다. UI는 좁은 화면에도 반응하지만 현재 비행 조작에는 키보드와 마우스가 필요합니다.
